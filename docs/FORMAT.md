# 目录数据格式 v1

每个文件代表一个学院的一份目录版本。推荐 JSON，CSV 适合从 Excel 导出。

## 顶层 JSON

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| schemaVersion | 数字 | 当前为 1 |
| name | 文本 | 目录名称，导入前可编辑 |
| institution | 文本 | 学校名称 |
| department | 文本 | 学院名称 |
| version | 文本 | 学校目录版本，和插件版本无关 |
| source | 文本 | 来源文件名、网址或页码；只作文本展示，不自动打开网址 |
| journals | 数组 | 必填、非空，每个元素代表一条期刊评级记录 |

## 期刊记录

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| title | 文本 | 必填，标准刊名 |
| grade | 文本 | 必填，保留学院原始等级，如 A类、权威、一级 |
| aliases | 文本数组或分号分隔文本 | 已核实属于该刊的别名、简称、原始目录写法 |
| issn / eissn | 文本数组或分号分隔文本 | 纸刊与电子版编号；未知留空，填写时验证校验位 |
| subject | 文本 | 学科；相同期刊按学科有多个等级时保留独立记录 |
| notes | 文本 | 来源原文中的限制、说明、人工核对事项 |

同一期刊跨学科有不同等级时，插件会显示“待确认”，用户可打开“依据”阅读各条记录。第一版没有学科上下文自动判断。

## CSV

文件应为 UTF-8（支持 BOM），第一行为表头。必需列 `title,grade`；其他列可选。不要在数据前添加说明行，不要输出 Markdown 表格。

```csv
title,aliases,issn,grade,subject,notes,institution,department,version,source
R&D Management,R & D Management;RD Management,,示例等级,,,示例大学,管理学院,2026版,示例来源
```

也接受中文表头：期刊名称、名称别名、等级、学科、备注、学校、学院、目录版本、来源。`e-issn` 可作为电子 ISSN 列。

- 同文件各行的学校、学院、版本和来源必须一致（空单元格可省略）。不同目录应分开导入。
- 别名和多个 ISSN 使用 `;`、`；`、`|` 或单元格内换行分隔，不用逗号分隔别名。
- 含逗号、引号或换行的单元格要用 CSV 双引号包围；单元格内的双引号写成两个双引号。
- 在 Excel 中把 ISSN 列设为文本，再另存为 **CSV UTF-8**；避免丢失前导零。
- 只允许一个名称列和一个等级列等，不要同时放 `title` 与 `期刊名称` 这样的重复语义列。

## 别名及安全处理

插件只把上传内容当数据处理，使用文本方式渲染，不执行文件内指令、HTML 或脚本。AI 的说明文字或文件中的操作要求都不构成插件指令。

自动统一大小写、Unicode 全半角、连续空白、常见弯引号和连接号、`&` 两侧空格。不会全局删除标点、替换 and 为 &、展开缩写或猜测期刊身份；这些关系应写入经过核实的 aliases。

无效行会使整次导入失败，现有目录保持不变；冲突行可以导入，但导入预览会提示，实际匹配标为“待确认”。未确认等级的记录应从可导入目录中移出并单独核查，不用猜测补齐。
