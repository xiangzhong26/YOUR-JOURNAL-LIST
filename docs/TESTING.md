## 你可以这样试用（约 5 分钟）

1. 在 Zotero 的“工具 → 插件”中，从文件安装 `dist/your-journal-list-0.1.3.xpi`。插件名称为 **Your Journal List · 学院期刊目录**。
2. 新建一个“插件测试”集合，通过“文件 → 导入”导入 `examples/demo-items.ris`，选择导入到新集合。
3. 点击列表工具栏“学院等级”，或工具菜单中的“学院期刊目录 / Your Journal List”。
4. 导入 `examples/demo-journals.json`。预览中会出现 **Shared Review 的冲突提示**，这是故意构造的测试。点击“确认并启用”。
5. 在 Zotero 文献列表的表头上右键，勾选“学院等级”。点击这列表头可以排序。
6. 对照下表检查等级：

| 测试条目 | 期刊写法 | 预期结果 |
| --- | --- | --- |
| DEMO 1 | R&D Management | A类 |
| DEMO 2 | RD MANAGEMENT | A类 |
| DEMO 3 | R & D Management | A类 |
| DEMO 4 | J. Example Stud. | B类 |
| DEMO 5 | Shared Review | 待确认 |
| DEMO 6 | Unknown Journal | 目录未收录 |
| DEMO 7 | 无刊名、无 ISSN | 信息不足 |
| DEMO 8 | 不同刊名 + ISSN 0033-6807 | A类 |

所有评级均为演示用虚构等级。

7. 打开管理窗口，点击“刷新当前列表”。选择 A类应显示 4 篇，B类显示 1 篇，“待确认”状态显示 1 篇。点击“依据”查看标准名、别名和备注，点击“定位”跳回原文献。
8. 再导入 `examples/demo-journals.csv`，作为新增目录启用。它只有前两本期刊，所以 Shared Review 应变成“目录未收录”。切换回 JSON 目录后恢复“待确认”。
9. 导出当前目录，重新导入导出的 JSON；检查记录和别名没有丢失。
10. 关闭并重新启动 Zotero，检查当前目录和等级仍在。停用插件时按钮和等级列应消失，重新启用后恢复。

## 发布前再检查

- 导入文件选择器可正常打开与取消；取消不会导入。
- 新增目录会保留旧目录；替换前弹出提示；导出取消不会显示成功。
- 导入缺少 grade、非法 ISSN 或损坏 JSON 时提示错误，已有目录不变。
- 搜索词包含 `<`、`>`、引号时仍然是文本，不执行代码。
- 主窗口切换集合后刷新，筛选范围随当前列表改变；阅读器中只取得当前文章。
- 浅色/深色界面、窗口缩放、表格滚动、键盘 Tab 焦点均可用。
- 若准备声明旧版支持，分别在 Zotero 7/8/9 测试安装、列显示、文件选择器和停用清理；否则在 Release 中明确“仅实测 Zotero 10.0.6 / Windows”。

## 开发者自动化命令

```powershell
npm run check
npm test
npm run build
python scripts/smoke_zotero.py
```

最后一条默认调用 `C:/Program Files/Zotero/zotero.exe`，也可用 `--zotero "可执行文件完整路径"`。该集成脚本目前按 Zotero 10 的调试协议实现；会在新临时 profile 内启用仅本机可连接的临时调试端口，通过 Zotero 的插件安装接口加载插件，结束后只关闭此测试实例。测试报告与日志保留在输出的临时目录中；不会给你的日常 profile 安装插件。CI 只运行前面三个命令。

目录规则或存储损坏可在 Zotero“工具 → 开发者 → 错误控制台”查看错误。提交 Issue 时提供最小样例和版本，不要上传完整私人文献库。
